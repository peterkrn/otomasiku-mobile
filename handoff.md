## Key Architecture

### Repositories are the only HTTP layer
```
Screens → Providers (Riverpod) → Repositories (Dio) → Express API
```
All 6 repositories are wired in `lib/providers/repository_providers.dart`. Screens call providers, providers call repositories — never Dio directly.

### ApiResponse shape expected from Express
```json
// Success
{ "success": true, "data": { ... } }
// Error  
{ "success": false, "error": { "code": "MACHINE_CODE", "correlationId": "uuid" } }
```

### Error handling pattern
- HTTP 4xx → `ApiInterceptor` catches → `ApiException(code, statusCode, details)`
- HTTP 5xx → `ApiInterceptor` catches → `ServerException(correlationId)`
- 2xx with `success: false` → Repository throws `ApiException` directly
- Screen catches via `.when(data: ..., error: ...)` on Riverpod providers

### Auth token injection
`ApiInterceptor` reads `Supabase.instance.client.auth.currentSession.accessToken` and adds `Authorization: Bearer` header automatically. No manual token handling in feature code.

### Connectivity
`connectivityProvider` is a `StreamProvider<bool>`. Use `OfflineBanner` widget (`lib/shared/widgets/`) to show when offline.

### Known issue with `flutterfire configure`
The original error (`UnimplementedError: Neither build.gradle nor build.gradle.kts were found`) was caused by:
1. No root-level `android/build.gradle.kts` existing
2. `android/app/build.gradle.kts` containing root-project config instead of app module config
3. `settings.gradle.kts` having `include(":app")` concatenated with `allprojects {` on the same line

All three are now fixed. Re-running `flutterfire configure --project=otomasiku-mobile` should work.
